How I work

Design first. I draw the system before I write it — boundaries, data flow, what can fail — and put the drawing in front of someone before code exists. Most of the drawings on this site started that way.

Test first. The test describes the behaviour; then the smallest code that passes; then clean up. A year at Incubyte made this a reflex rather than a preference.

With an AI pair. Context, then an explicit plan, then review of the plan, then code, then review again, then commit. I spend my attention on the plan; the diff is where the plan shows. I wrote the loop up in Review the plan, not the diff.
